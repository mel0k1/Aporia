# Железо и загрузка

Aporia наследует от базы драйверную поддержку уровня «минимальный сервер»: PCI, ACPI, APIC, таймеры TSC и HPET-совместимый слой, NVMe для дисков, virtio для виртуальных машин, i8042 для клавиатуры PS/2, UART для последовательной консоли и DRM с simpledrm для вывода на framebuffer, который прошивка оставила после UEFI. Релизный артефакт — ISO с GRUB: меню загрузки называется `Aporia`, ядро стартует по linux-протоколу загрузки (bzImage), который GRUB поддерживает и на UEFI-системах, и на legacy BIOS. Это значит, что один и тот же ISO загружается и в QEMU, и на физической машине с USB-флешки.

## Загрузка с USB на реальной машине

Порядок проверен на сборке `make kernel` и ISO из Release: кодовая база читает загрузочный носитель только через прошивку и GRUB, поэтому для загрузки достаточно флешки объёмом от 512 МБ. Ядро в этот момент уже находится в памяти, и отсутствие в нём USB-хост-драйверов на шаг загрузки не влияет.

1. Записать ISO на флешку побайтово: `sudo dd if=aporia-x86_64.iso of=/dev/sdX bs=4M status=progress oflag=sync`, подставив устройство флешки вместо `/dev/sdX`. В Windows подойдёт Rufus в режиме DD или balenaEtcher.
2. Выключить Secure Boot: база не подписывает bzImage и не содержит ключей для проверки подписи, поэтому с включённым Secure Boot GRUB откажется грузить ядро.
3. Открыть boot menu прошивки (обычно F12, F11 или Esc), выбрать флешку. Появится меню GRUB с единственным пунктом `Aporia`.
4. Дождаться приглашения shell из initramfs. Если вывод не появился на экране, подключить терминал к последовательному порту: ядро пишет логи в UART-компонент, и консоль по serial — штатный путь отладки на железе.

## Что ожидать и чего ждать не стоит

Внутри initramfs доступны базовые проверки: дерево устройств в `/sys`, `/proc`, блочные устройства NVMe в `/dev`. Клавиатура работает через i8042 на машинах, где порт PS/2 физически разведён или прошивка эмулирует его для USB-клавиатуры (на большинстве десктопов и серверов эмуляция включена по умолчанию). Сеть на реальном железе работать не будет: из сетевых драйверов в базе есть только virtio-net, который вне гипервизора не существует. Диски подключаются через NVMe; SATA/AHCI и USB-накопители как блочные устройства ядро пока не видит. Графика ограничена framebuffer от прошивки через simpledrm — никакого ускорения или выбора видеорежимов.

Иными словами, реальное железо сегодня — это способ проверить загрузочные пути (UEFI handover, multiboot, legacy32), PCI-перечисление, ACPI-таблицы, таймеры и NVMe вне QEMU. Всё остальное — задача следующих этапов, и она закрывается по мере развития проекта.

## Конфиденциальные вычисления

База поддерживает Intel TDX: ядро умеет работать как доверенная среда выполнения внутри защищённой виртуальной машины. Этот путь требует хост-стека TDX и процессоров с поддержкой технологии; в тестовом контуре Aporia он пока не подключён, потому что для него нужна соответствующая железная инфраструктура, а не обычный runner. Когда появится доступ к TDX-машине, регрессионный набор `intel_tdx` подключается в тяжёлый контур без изменений в самих тестах.
